# iPhone 連携ガイド（ショートカットで自動送信）

使うアプリ：**体重＝タニタ（ヘルスプラネット）／睡眠＝Sleep Cycle／食事＝カロミル／筋トレ＝フィットネスポイント**

4つのアプリはそれぞれ別ですが、どれも **Apple ヘルスケア** にデータを書き込めます。
ヘルスケアを集約先にして、iOS 標準の **ショートカット** アプリから自動で GitHub に送ります。

```
タニタ（ヘルスプラネット）── 体重・体脂肪率 ─┐
Sleep Cycle ──────────────── 睡眠 ───────┤
カロミル ──────────────────── 摂取エネルギー・PFC ─┼─▶ ヘルスケア ─▶ ショートカット ─▶ GitHub ─▶ ダッシュボード
フィットネスポイント ────────── ワークアウト ───┤
iPhone / Apple Watch ──────── 歩数 ───────┘
```

---

## ステップ1：各アプリのヘルスケア連携をオンにする

アプリによって設定メニューの名前が少し違います。「ヘルスケア」「Apple Health」「外部連携」などの項目を探してください。
ヘルスケアへの **書き込み**（データを送る側）を許可するのがポイントです。

### タニタ（ヘルスプラネット）
1. アプリの設定 →「ヘルスケア」連携をオン
2. ヘルスケアの許可画面で **体重**・**体脂肪率**（あれば除脂肪体重も）の書き込みをオン
3. 体組成計で測った値は、まず **アプリに転送されてから** ヘルスケアに入ります。測定したらアプリを開いて転送を完了させてください（後で「アプリを閉じたら同期」を設定します）

### Sleep Cycle
1. Sleep Cycle → 設定 →「Apple ヘルスケア」をオン → **睡眠分析** の書き込みを許可
2. 睡眠データは、朝 **アラームを止めて睡眠記録が終わったとき** にヘルスケアへ書き込まれます

### カロミル
1. カロミル → 設定（マイページ）→「ヘルスケア連携」をオン
2. **摂取エネルギー（食事エネルギー）・タンパク質・脂質・炭水化物** の書き込みを許可
3. 体重を読み込む許可もオンにしておくと、カロミル側の体重記録も自動で揃います（読み込みだけなので二重には送られません）

### フィットネスポイント
1. フィットネスポイント → 設定 →「ヘルスケア（Health）」をオン → **ワークアウト** の書き込みを許可
2. ワークアウトは、アプリでトレーニングを **終了（完了）したとき** に保存されます
3. フィットネスポイントで体重も記録している場合は、**体重の書き込みはオフ** にしてください（タニタの値と二重になるため）

### 連携できているかの確認（重要）

**ヘルスケアアプリ → ブラウズ** で各項目を開き、下までスクロールして **「データソースとアクセス」** を見ます。

| 確認する項目 | 表示されていてほしいアプリ | チェック |
|---|---|---|
| 身体測定値 → 体重 / 体脂肪率 | ヘルスプラネット | ☐ |
| 睡眠 | Sleep Cycle | ☐ |
| 栄養 → エネルギー摂取量 / タンパク質 / 脂質 / 炭水化物 | カロミル | ☐ |
| アクティビティ → ワークアウト | フィットネスポイント | ☐ |

**睡眠の追加確認**：睡眠 →「すべてのデータを表示」で、Sleep Cycle のデータが **「睡眠（コア/深い/レム）」** なのか、**「就寝中（ベッドにいた時間）」だけ** なのかを見ておいてください。
このあと作るショートカットはどちらにも対応していて、「睡眠」があればそれを、なければ「就寝中」を睡眠時間として使います。

> ヘルスケアに出てこないアプリがあっても大丈夫です。その項目だけ「ステップ5：手入力ショートカット」で送れます。

## ステップ2：GitHub のトークンを作る（1回だけ）

1. GitHub → 右上アイコン → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. 設定
   - Token name: `bodymake-iphone`
   - Expiration: 最長（1年）
   - Repository access: **Only select repositories → `bodymake`**
   - Permissions → Repository permissions → **Contents: Read and write**（他は不要）
3. 生成された `github_pat_...` をコピーします（この画面でしか表示されません）

## ステップ3：ショートカット「BodyMake 同期」を作る

ショートカットアプリ → 右上「＋」→ 以下のアクションを上から順に追加します。
アクションは「アクションを検索」に **太字の名前** を入れると見つかります。

各検索には **「ソース」フィルタ** を付けます。こうしておくと、Apple Watch など他のアプリの値が混ざって二重に数えられることを防げます。
（フィルタ追加 → 「ソース」→ 「である」→ アプリを選択）

### 3-1. 日付
1. **日付** →「現在の日付」
2. **日付をフォーマット** → 形式「カスタム」、書式 `yyyy-MM-dd` → 変数名を `日付` に変更（結果を長押し →「名前を変更」）

### 3-2. 体重・体脂肪率（タニタ）
3. **ヘルスケアサンプルを検索**
   - 種類: **体重**
   - フィルタ: 開始日 が **今日** / ソース が **ヘルスプラネット**
   - 並べ替え: 開始日・**古い順** / 制限: **1件**
   - → 変数名 `体重`
   - ※ 朝起きてすぐの測定を毎日の基準にするため「古い順の1件目」を使います（1日に何回測っても朝の値で比較できます）
4. 同様に **体脂肪率**（ソース：ヘルスプラネット・古い順・1件）→ 変数名 `体脂肪`

### 3-3. 睡眠（Sleep Cycle）
5. **ヘルスケアサンプルを検索**
   - 種類: **睡眠分析**
   - フィルタ: 開始日 が **過去1日** / ソース が **Sleep Cycle** / 値 が **就寝中ではない** / 値 が **覚醒ではない**
6. **ヘルスケアサンプルの詳細を取得** → **継続時間**
7. **統計を計算** → **合計** → 変数名 `睡眠`
8. もう一度 **ヘルスケアサンプルを検索**（睡眠分析・過去1日・ソース Sleep Cycle・値 が **就寝中である**）
9. **ヘルスケアサンプルの詳細を取得** → **継続時間** → **統計を計算** → **合計** → 変数名 `就寝中`

### 3-4. 食事（カロミル）
10. **ヘルスケアサンプルを検索** → 種類 **エネルギー摂取量**（「摂取エネルギー」と表示される場合あり）、開始日が **今日**、ソースが **カロミル** → 変数名 `カロリー`
11. 同様に **タンパク質** / **脂質** / **炭水化物**（いずれも今日・カロミル）→ 変数名 `P` / `F` / `C`
    - 朝・昼・夜など複数件あっても、受け取り側で自動的に合計します

### 3-5. トレーニング（フィットネスポイント）・歩数
12. **ヘルスケアサンプルを検索** → 種類 **ワークアウト**、開始日が **今日**、ソースが **フィットネスポイント** → 変数名 `筋トレ`
    - フィットネスポイントの記録は、種類名に関係なく **すべて筋トレ1回** として数えます
13. （Apple Watch でランニングやウォーキングも記録している場合）**ヘルスケアサンプルを検索** → 種類 **ワークアウト**、開始日が **今日**、ソース が **フィットネスポイントではない** → 変数名 `有酸素`
14. **ヘルスケアサンプルを検索** → 種類 **歩数**、開始日が **今日**（ソースの指定なし）→ **ヘルスケアサンプルの詳細を取得 → 値** → **統計を計算 → 合計** → 変数名 `歩数`
    - ※ iPhone と Apple Watch の両方を使っていると、歩数が多めに出ることがあります。気になる場合は、ソースを「iPhone」に絞ってください

### 3-6. GitHub に送信
15. **URLの内容を取得**
    - URL: `https://api.github.com/repos/osamutakesawa-hub/bodymake/dispatches`
    - 方法: **POST**
    - ヘッダ:
      | キー | 値 |
      |---|---|
      | `Authorization` | `Bearer github_pat_xxxxxxxx`（ステップ2のトークン） |
      | `Accept` | `application/vnd.github+json` |
    - 本文を要求: **JSON**
      | キー | 型 | 値 |
      |---|---|---|
      | `event_type` | テキスト | `health-sync` |
      | `client_payload` | 辞書 | ↓ |

    `client_payload`（辞書）の中身：

    | キー | 型 | 中身 |
    |---|---|---|
    | `date` | テキスト | `日付` |
    | `weight` | 辞書 | `kg` → `体重`、`bodyFatPct` → `体脂肪` |
    | `sleep` | 辞書 | `minutes` → `睡眠`、`inBedMinutes` → `就寝中` |
    | `nutrition` | 辞書 | `kcal` → `カロリー`、`proteinG` → `P`、`fatG` → `F`、`carbsG` → `C` |
    | `activity` | 辞書 | `steps` → `歩数` |
    | `strengthWorkouts` | テキスト | `筋トレ` |
    | `workouts` | テキスト | `有酸素`（手順13を作らなかった場合は省略） |

16. 名前を **BodyMake 同期** にして保存します。▶︎ で一度実行し、ヘルスケアへのアクセスを「すべて許可」します

GitHub → リポジトリ → **Actions → Sync health data** に実行が表示されれば成功です。
ログの `Ingest` に保存した項目（例：`saved 2026-11-02: weight, sleep, nutrition, activity, workouts`）が出ます。

### 値の形式について
ショートカットが返す値の形式はiOSのバージョンで多少違いますが、受け取る側で吸収します。
- `72.4 kg`、`2,100 kcal` など単位付きの値 → 数値部分を使います
- 睡眠：`7:12`、`7時間12分`、`7.2`（時間）、`432`（分）、`25920`（秒）のどれでもOK
- 体脂肪率：`18` でも `0.18` でもOK
- 空の項目は無視します（その日の既存データは消えません）

## ステップ4：自動実行（オートメーション）

ショートカットアプリ → 下の **オートメーション** → ＋ → **個人用オートメーション** を作ります。
すべて **「すぐに実行」**、アクションは **ショートカットを実行 → BodyMake 同期** です。

| トリガー | タイミング | 送られるもの |
|---|---|---|
| **App** → **Sleep Cycle** を「閉じたとき」 | 朝、アラームを止めた後 | 睡眠 |
| **App** → **ヘルスプラネット** を「閉じたとき」 | 体組成計で測ってアプリに転送した後 | 体重・体脂肪率 |
| **App** → **カロミル** を「閉じたとき」 | 食事を記録するたび | カロリー・PFC |
| **App** → **フィットネスポイント** を「閉じたとき」 | トレーニング終了後 | 筋トレ |
| **時刻** 毎日 22:30 | 1日の締め（取りこぼし対策） | 全項目 |

同じ日に何回送っても、届いた項目だけが上書きされるので問題ありません。

> **注意**：iPhone がロックされているとヘルスケアを読めず、空のまま送られることがあります（空の項目は無視されるので害はありません）。
> アプリを閉じたときのトリガーは iPhone を操作中なので、確実に動きます。

### 毎朝のルーティン（おすすめ）
1. 起床 → Sleep Cycle のアラームを止める（→ 睡眠が自動送信）
2. トイレの後に体組成計で測る → ヘルスプラネットを開いて転送（→ 体重が自動送信）
3. ダッシュボードを開いて、今日の目標カロリーとトレーニングメニューを確認

### 夜遅くに食事を記録した場合（任意）
22:30 より後にカロミルで記録しても、カロミルを閉じた時点で送信されるので基本的には大丈夫です。
日付が変わってから前日分を記録した場合は、ショートカットを複製して「BodyMake 同期（昨日）」を作ります。手順1の後に **日付を調整 → 1日を減算** を入れ、検索条件の「今日」を「昨日」に変えて、手動で実行してください。

## ステップ5：手入力ショートカット（連携できない項目の予備）

どれかのアプリがヘルスケアに書き込めない場合は、その項目だけ手入力で送れます。
（例：カロミルの1日の合計画面を見て入力する、フィットネスポイントでトレしたら「筋トレ」をタップする、など）

「BodyMake 手入力」ショートカットを作ります。

1. **日付** → **日付をフォーマット**（`yyyy-MM-dd`）→ `日付`
2. **メニューから選択**：`食事` / `筋トレした` / `有酸素した` / `体重`
   - **食事**：**入力を要求**（数字）を4回 →「カロリー」「タンパク質」「脂質」「炭水化物」→ それぞれ変数に
   - **筋トレした** / **有酸素した**：**テキスト** に `筋トレ` / `有酸素` → 変数 `手入力トレ`
   - **体重**：**入力を要求**（数字）→ `体重`
3. **URLの内容を取得**（ステップ3-6と同じURL・ヘッダ）。`client_payload` は入力した項目だけを入れます：
   - 食事：`date`、`nutrition`（`kcal` / `proteinG` / `fatG` / `carbsG`）
   - トレ：`date`、`manualWorkout` → `手入力トレ`
   - 体重：`date`、`weight`（`kg`）
4. ホーム画面に追加しておくとワンタップで使えます

## 手動で送る・過去分をまとめて送る

Actions → **Sync health data** → **Run workflow** の `payload` 欄に JSON を貼り付けます。

```json
{"days":[
  {"date":"2026-11-01","weight":{"kg":74.8,"bodyFatPct":19.8},"sleep":{"minutes":410},"nutrition":{"kcal":2200,"proteinG":140}},
  {"date":"2026-11-02","weight":{"kg":74.6},"strengthWorkouts":"ベンチプレスの日"}
]}
```

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| Actions に実行が出ない | URL、`Authorization: Bearer ` の後のトークン、トークンの権限（Contents: Read and write）と期限 |
| 401 / 404 が返る | トークンの対象リポジトリに `bodymake` が含まれているか |
| 体重が空になる | ソースフィルタのアプリ名が、ヘルスケアの「データソースとアクセス」に出ている名前と同じか |
| 体重が2倍の値になる | 体重の検索が「制限：1件」になっているか |
| 睡眠が0になる | Sleep Cycle が「就寝中」しか書かない場合も `inBedMinutes` で拾えます。手順8〜9が入っているか確認 |
| 睡眠が長すぎる | Apple Watch の睡眠と二重になっていないか（ソースフィルタ） |
| 筋トレがカウントされない | フィットネスポイントでワークアウトを「終了」したか、ワークアウトの書き込みがオンか |
| 食事が入らない | カロミルの連携設定で栄養素の **書き込み** が許可されているか。だめなら手入力ショートカットで代用 |
| ダッシュボードが更新されない | ワークフローが **デフォルトブランチ（main）** にあるか（iPhoneからの同期はデフォルトブランチでしか動きません） |
